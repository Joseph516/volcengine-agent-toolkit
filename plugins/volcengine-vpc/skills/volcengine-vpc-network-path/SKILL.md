# VPC 网络路径与最小放行

从真实源/目的地址定位接口与关联策略，交付有证据的阻断层、最小改动和影响范围。
资源名称不表示转发角色；存在规则不表示规则已关联生效；Available/Active不证明业务可达。

## 范围与取证

- 确定源、目的、协议、目的端口、地址族、地域和目标时间。缺少实际端口时给条件结论，
  不替用户猜端口。历史问题保留故障时间，当前查询不能替代历史配置。
- 使用已安装的 `volcengine-cli` 获取实际接口帮助及字段语义；按用户已选身份和地域查询，
  不自行切换身份。每次调用带 `VE_CALLER_TYPE=ai_agent`、实际宿主的 `VE_CALLER_NAME`、
  `VE_SKILL_NAME=volcengine-vpc-network-path`。不打印凭据或整份环境变量。
- 精确地址定位 ENI，再核对 VPC、子网、挂载实例、全部关联 SG、ACL 和路由表。
  不把实例的第一张网卡当成目标网卡，不把 ACL/VPC 同属一个 VPC 当成已绑定。
- 规则和影响面查询要保留完整分页、错误回执、查询参数、时间和 RequestId。
  字段不存在、投影为 null、截断或 403 均不是零对象；回看原始返回，仍无法确定则未知。
  查询共享 SG 关联时包括未挂载 ENI，不能用 ECS 列表替代全量关联查询。
- 用户仅授权指定对象时，不为补全影响面越界读取其他对象明细；只枚举定位允许的ID。
  所需关联证据超出授权时列出缺口，不能宣称影响面已完整。

## 路径与策略判断

按实际请求/响应和本轮读到的官方语义处理规则优先级、默认动作、多SG聚合与地址族。
不猜厂商优先级、字段、隐式放行或同优先级处理。用 `volcengine-knowledge-search`
核对产品细节；找不到时保留未知，不能将别家云语义移植过来。

1. 检查源首次出向 SG 和目的首次入向 SG；有状态的回程豁免不能用于首次发起。
2. 分别检查源/目的 ACL 的正向与反向。无状态 ACL 的返回流源端口是服务端口、
   目的端口是客户端实际临时端口；不能把只放双向服务端口视为完整回程。
   没有客户端端口范围证据时不自行扩大授权范围。
3. 将各层的有效策略共同判断。ACL宽允许、SG精确限制可以共同限制业务，
   不能强制每一层都必须单独有/32或/128规则，也不能仅凭ACL宽规则判公网已暴露。
4. 路由先检查目标子网实际关联，再做最长前缀匹配；同前缀多候选按产品规则核实。
   下一跳名字不是“正确网关”证据，还需设计意图、挂载和转发能力、回程/NAT等证据。
5. 将已核验且同时间点的关卡交给离线校验器组合。历史日志 REJECT 不直接定位 SG/ACL，
   NODATA不证明客户端停止，未定义结果码不推出TCP报文序列。

## 最小放行与计算

固定一条协议/端口流，分别列允许的源和目的集合、修改后有效集合。
共享 SG 的新增规则可能影响所有关联 ENI；source/32只限制源，不限制目的。
需要“只放这一对”时，考虑独立策略绑定或其他支持的隔离方式，并核验既有绑定/规则
不会继续扩大范围。不要删除共享规则或仅新增accept就声称收窄原有允许范围。

使用 [scripts/check_network.py](scripts/check_network.py) 校验 CIDR 集合扩张、最长前缀和
关卡组合。输入契约及命令见 [references/checks.md](references/checks.md)。
这是离线校验器，不是云API字段转换器或完整产品防火墙模拟器；Agent必须基于原始证据
整理有效集合/关卡，不能虚构 complete、applicable 或 allow 来满足输入。

## 交付与验证边界

- 先回答已确认的配置问题，给出精确影响范围、必要改动与尚缺证据；不要扩写未经核实的旁支结论。
- 分别标记配置推演、配置回读、实际连接验证。只有真实端点探测和服务状态等证据才能
  声称业务已通；现有工具不支持端点探测时明确缺口，不凭配置计算宣称成功。
- 写操作按用户当次授权另行执行；本Skill默认只给方案。不能给任意写接口加DryRun就当模拟。
  用户授权执行时，按CLI/变更流程保存前态、执行、回读、影响面与适当数据面验证；失配即停止续写。
- 不把“未挂载”“无ECS引用”“测试命名”视为无依赖或可清理；不承诺修改单项后一定恢复。
